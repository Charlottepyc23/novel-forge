# 编剧规范（剧情骨架标准化基准）

> 骨架的 `function`（叙事功能）与 `emotion`（情绪走向）取值基准，统一来自 `src/story-beat-language.ts`。
> 目的：让"叙事功能 / 情绪链"有标准词表，避免 LLM 自由发挥导致情绪走向漂移。

## 数据结构

`StoryboardBeat` 的编剧字段已从自由字符串改为**受控枚举**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `function` | `StoryFunctionId` | 叙事功能，单选 |
| `emotion` | `EmotionId[]` | 情绪走向，链式数组 |

## 词库（src/story-beat-language.ts）

### 叙事功能 `function`（单选）
| id | 中文 | 说明 |
|---|---|---|
| `exposition` | 铺垫 | 介绍背景/人物/悬念 |
| `conflict` | 冲突 | 矛盾显现/加剧 |
| `turn` | 转折 | 剧情反转/方向改变 |
| `climax` | 高潮 | 冲突顶峰/揭示 |
| `resolve` | 收束 | 矛盾化解/结果 |
| `foreshadow` | 伏笔 | 埋下后续线索 |
| `character` | 人物塑造 | 展现人物特质/转变 |

### 情绪 `emotion`（链式数组，按情绪发展顺序）
按能量/阶段分四组：
- **起（低能量）**：平静、淡然、期待、好奇、警觉
- **承（蓄势）**：压抑、隐忍、担忧、焦躁、不安
- **转（激化）**：惊惧、愤怒、崩溃、决绝、痛心
- **合（落点）**：释然、悲凉、得意、重生、麻木

## 数据流

1. **LLM 生成**（`generateStoryboardSkeleton`）：system prompt 限定 function/emotion 词表，LLM 输出标准中文 → 经 `normalizeStoryFunction / normalizeEmotions` 归一化到枚举 id。
2. **存量数据**：旧自由文本骨架在读取时自动归一化（StoryboardTab `setSkeleton` 处）。
3. **展示**：前端用 `functionZh / emotionZh` 转回中文（emotion 用 → 连接）。前端 badge 依 `function` 着色（climax→绿、turn→黄）。

## 约定

- **主题=颜色、密度=尺寸、镜头=分镜词表、节拍=编剧词表**：新增编剧字段一律从词库取值，禁止自由文本。
- 新增词条：在 `story-beat-language.ts` 的 `STORY_FUNCTIONS / EMOTIONS` 追加，并同步 normalize 函数。
